## 运行约定

从项目根目录调用脚本，例如：

```bash
python3 scripts/030/build_030_n1_challenger.py
```

030 构建器只生成 notebook、metadata 和来源记录；它会写入 `notebooks/030/`，不会启动 Kaggle。当前成品已保存，接手先读 [030 进展](../docs/progress/030-n1-challenger-and-score-strategy.md)。不要把重新构建当作模型运行或公榜得分。

各历史脚本的依赖、输入、参数和已实际执行命令见对应进展。部分脚本使用相对于项目根目录的数据路径，因此不从轮次子目录运行。已改用脚本位置推断根目录的入口按 `scripts/轮次/文件.py` 两层布局定位；跨轮次依赖显式加入对应脚本目录。

本次整理改变了脚本路径及路径适配代码，历史产物记录的源码 hash 对应当时版本，不应改写为当前 hash。旧结果及修复前记录继续保留；重跑前查看脚本的覆盖行为和进展中的适用边界，尤其是会直接改写旧 notebook 的 `legacy/patch_sub_v6.py`。
