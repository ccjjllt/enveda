# 021 — E006 基线的本地 NP250 验证

日期：2026-10-20。接手`374f1a8`，承接020（v11 原样复现 public 0.446）。对应[021进展](../progress/021-local-validation.md)。

## 问题

v11 之上的每个改动若都靠 public 判断，既耗 GPU 与提交次数，又只看 31% 测试数据、波动大。需要一个本地 CPU 验证器，回答：**哪些改动在「有参考 / 无参考 / 结构不在池」三种条件下分别帮忙或伤害？** 先用它筛选 v12 候选，再用一次提交确认。

## 假设

- E006 的 CPU 阶段（Engine1 v4n、Engine2、PubChem 通道、LightGBM 排序、门控与融合）可在 box 上原样执行；ICEBERG/GLACIER 需 GPU，跳过后结果是去模拟器的相对比较。
- 有参考与无参考场景的方向可能相反（018 已见扩库强化错误匹配），所以单一遮蔽的正收益不足以上线。

## 实验设计

面板：train 中 `enveda-np-examples` 1184 谱 / 250 结构（与 iceberg-np250 / glacier-np250 同批），按官方指标身份成组。评分用官方 metric 原样代码（RDKit 2026.03.3）。

遮蔽：
- A 全可见（上界）；
- B 只隐藏查询谱本身，保留其他来源同结构参考；
- R 删除与真值同一身份的所有谱，结构仍在池；
- C = R＋从 Engine1/Engine2/PubChem 池移除真值身份，生成路径仍允许命中。

步骤：
1. 原样执行 E006 notebook 的代码单元（路径重定向、跳过 GPU 预检与模拟器），得到 B、C（及可行时 A）的基线 MRR。
2. 每次只加一个改动，与基线逐分子配对，报告 Δ、wins/losses、bootstrap 95% CI：
   - MassBank 538 结构追加到 Engine2 池；
   - 直接参考质量（只用跨来源参考）后处理提升；
   - 小范围门参数扫描：LIB_TAU、REL_TH、PubChem 提升阈值 PROMO_REL、POP_TAU、融合窗口。
3. 核对 C 中剩余命中来自哪个通道。

## 成功标准

- 验证器能端到端跑通并与官方 metric 一致。
- 候选改动需在 B 上有正收益且在 C 上不伤害，才推荐进入 v12；只在 B 上有利的改动必须标注风险。
- 面板小且与 018/019 复用，所有正 Δ 只作提交候选筛选，不声称提分。

## 算力

box 8 CPU / 15 GB，无 GPU。单次全流程约 80 分钟；门扫复用 Engine2 / PubChem 输出，只重跑尾部。不占 Kaggle GPU，不提交。
