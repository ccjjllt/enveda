# 001 — 数据理解与检索排序基线

对应进展：[001-baseline](../progress/001-baseline.md)。创建日期：2026-09-30。

## 背景与需要继承的结论

这是 MS/MS 到分子结构的识别比赛，以分子级 MRR@25 评分；输入是多张谱，输出是每个分子的有序 SMILES 列表。训练集约 3.03 GB，M5 / 32 GB 适合小样本与分块处理，完整模型计算优先远端。

当前可见 test 仅为训练抽样的占位数据。隐藏集包括已有公开谱、只有数据库结构、数据库外分子三类，比例未知。不能把占位 test 当验证集，也不能把全体隐藏分子假定为训练结构之外。第三类需要后续 de novo 研究，检索基线有明确覆盖上限。

最终提交为 Kaggle 离线 notebook，CPU/GPU 上限 9 小时。外部私有云训练可行。项目不创建测试文件，所有检查手动发起并记录结果。

## 目标与假设

1. 建立可解释的本项目基线：数据划分、候选来源、排序证据、运行预算和提交产物均可追溯。
2. 假设 A：质量/adduct 过滤与谱库检索可以低成本识别有参考谱的分子。
3. 假设 B：神经指纹与多谱融合能改善无参考谱但候选库包含真值时的排序。
4. 假设 C：排序分数与候选覆盖率需要分开观察；真值未进入候选池时，单独改善排序无法解决问题。

上述假设尚未通过本项目实验验证。

## 数据与评估设计

- 下载/挂载完整训练集后先查看实际 schema、来源、adduct、仪器、结构和谱的去重情况。不要依赖 `molecule_id` 或 `spectrum_id` 必然存在于 train：讨论中已有缺列报告，但本项目尚未读取该文件。
- 按官方评分方式规范化结构，使用规范化后的 InChIKey14 定义结构分组。无效结构单独计数，不静默丢弃。
- **已见结构轨道**：结构允许存在谱库中，query 使用独立谱；去掉同谱、重复测量拷贝，尽可能按来源/采集条件划分。用于衡量合法谱库检索能力，明确“结构已见”。
- **未见结构轨道**：同结构的所有谱和跨来源重复归为一组，训练时整组留出；候选结构库可以包含真值，参考谱库不能包含留出结构的标注谱。用于衡量指纹与排序泛化。
- **库外轨道（后续）**：将结构候选池之外的分子单列，衡量覆盖盲区；这只是第三类问题的近似，不声称复制隐藏数据分布。
- 外部 pretrained checkpoint 可能已经见过本地 holdout。获取训练来源与划分后才能将结果称为严格未见结构泛化；否则标为“预训练暴露未知”，并保留从头训练或独立来源对照。
- 固定 seed 与分组清单，保存 split manifest。只在训练侧调整预处理/拟合统计，避免反复追逐同一小验证集。

核心指标按分子计算：MRR@25、Top-1、Top-25、候选池覆盖率、无效/重复 SMILES 比例、无候选比例和耗时。按仪器、adduct、正负模式、谱数分层；timstof 是主要关注域，但不要仅用占位 test 推断隐藏分布。

候选评测细节：空分号项在分配排名前删除；非空但无效的 SMILES 占排名且不命中。重复等价结构浪费候选位置，因此提交前按官方规范化 InChIKey14 去重，并保留最佳候选顺序。不要把自己的去重/过滤逻辑错误地当作 scorer 本身会执行的操作。

## 实验方案

| 实验 | 内容 | 要回答的问题 |
| --- | --- | --- |
| B0 | 质量/adduct 过滤 + 精确谱库/余弦匹配 | 已有谱的识别能力与候选覆盖上限 |
| B1 | 增加 analog 匹配、公开指纹 checkpoint 和重排 | 未见结构排序是否改善，耗时是否可接受 |
| B2 | 同分子多谱融合：单谱、合并谱、分数聚合 | 哪种融合对不同 adduct/碰撞能有效 |

每轮尽量只改变一个因素。按候选池覆盖率解释 MRR 变化，不把公开 leaderboard 分数或作者报告替代本项目结果。没有真实指标时只汇报实现状态。

## 拟实现的代码与产物

这些是下一步设计，**当前尚未创建**：

- `src/data.py`：Parquet 按列、按 batch 读取；谱标准化；元数据编码；结构分组与 split 导出。
- `src/retrieval.py`：adduct 到中性质量的处理、ppm 窗口、谱匹配、候选召回；精确质量计算保留足够精度。
- `src/ranking.py`：单谱与多谱候选合并、去重、指纹与检索证据排序。
- `src/evaluation.py`：手动研究用分子级评估，采用官方规范化/排名语义；这是实验代码，不是测试文件。
- `notebooks/baseline/baseline.ipynb` 与 `kernel-metadata.json`：自包含或显式挂载代码输入；输出 `submission.csv`、`metrics.json`、配置及运行摘要。
- `artifacts/001-baseline/`：划分清单、数据/权重来源与版本、指标、日志、提交产物，不入 Git。

只实现首轮实验实际需要的模块；如果一个简短 notebook 足够，不先拆成框架。

## 实现步骤

1. 阅读本轮进展与原始证据，拉取并固定参考 notebook 版本，记录许可证和权重来源。
2. 在 CPU 环境读取完整训练 schema，建立两类留出集和来源摘要；大数组分块存储。
3. 手动执行 B0，保存各轨道的覆盖率与排名指标。
4. 引入 B1，再做 B2；检查公开 checkpoint 的训练暴露情况。
5. 准备离线依赖、权重和候选库输入，用 Kaggle CLI push；记录 notebook 版本、状态和日志。
6. 人工核对输出列、ID 集合、候选格式/数量、SMILES、离线运行时间，然后按研究安排提交指定版本并记录真实返回分数。
7. 更新同名 progress，给 002 留下模型、划分、瓶颈、产物路径及值得微调的对象。

不需要自动化测试、CI 或形式化准入门控。人工发现问题后直接修复、重跑受影响部分。
