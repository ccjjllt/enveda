## 2. 需要撤回的算术与归因

### 2.1 单个 MRR 不能确定 top-1、recall@25 或新颖度比例

[069 管线图第 259 行起](/Users/zhaohuaxiang/ccjjllt/enveda/rounds/069-new-signals/research/069-pipeline-map.md:259)先假设 rank-1=0.43、recall@25≈0.72，之后把“28% 零分分子”当成实测。[070 class-2 文档第 18 行起](/Users/zhaohuaxiang/ccjjllt/enveda/rounds/070-generation/research/070-gap-is-class2.md:18)又假设三个类别等比例，并认定 class 1 全部已答对，最终将“差距几乎全部在 class 2”写成结论。

设 `a=top1`、`R=recall@25`、`m=MRR@25`，只知道：

```text
a + (R-a)/25 <= m <= a + (R-a)/2
```

只给 `m=0.492`，允许 `a` 从接近 0 到 0.492，允许 `R` 从 0.492 到 1。大量 rank-2 命中与少量 rank-1 命中可得到类似 MRR。没有隐藏逐题真值，不能从总分辨别“真值不在数据库”“在候选窗口但未进 25”“已进 25 但排错”。文档原表逐名次求和还得到约 **0.49546**，并非表中的 0.491；这只是一个假想分布。

同理，`275,810/710,701` 是**数据库结构的比例**，不是隐藏 query 类别比例；20/20 的 PUG REST 可达抽样也不能证明 3,719 个结构都在 notebook 挂载的历史 PubChem tier 中。在线 PubChem 可达、离线快照包含、质量窗口召回、pass-1 召回、最终 top-25 召回是五件不同的事。

### 2.2 没有统一的“0.51 精度门槛”

[070 生成文档第 178 行](/Users/zhaohuaxiang/ccjjllt/enveda/rounds/070-generation/research/070-pool-external-generation.md:178)把原 leader 正确的损失事件误写成 `(1-c)`，并把 rank 1→2 的损失写成 0.9；实际是 `1-1/2=0.5`。即使接受该错误损失式，解 `p=(1-p)A` 也应得到 `p=A/(1+A)`，不能直接取 `p=A`。因此后续所有用 0.51 否决模型、宽窗候选或训练方向的推导失效。

正确做法是对实际列表操作计算 ΔMRR。设候选身份已经按评分规则去重，`p_r` 为在**待执行该动作的分子子集内**旧第 r 名正确的概率。

**将已有第 k 名移到第一，其余相对顺序不变：**

```text
E[Δ | move k→1] = p_k * (1-1/k) - Σ[r=1..k-1] p_r / (r*(r+1))
```

真值是被提升候选时只增 `1-1/k`；真值原在其前面时下降一位；原在其后面或列表外时不变。例如把第二名换到第一，期望严格等于 `0.5*(p_2-p_1)`，不存在 0.51 常数。

**插入一个列表外的新候选到第一，保留前 24 名：**

```text
E[Δ | insert] = p_new - Σ[r=1..24] p_r / (r*(r+1)) - p_25/25
```

这里新候选正确与旧 leader 正确互斥，不能把两个边际精度当独立事件相乘。若忽略旧 2–25 名损失、把 `c0` 明确定义成“新候选错误时，旧 leader 正确的条件概率”，近似才是 `p-0.5*(1-p)*c0`，阈值 `c0/(2+c0)`；`c0=0.43` 时约 0.177。这个近似也不能用作通用阈值，因为真实中名次损失、候选原始名次、门控后的条件分布均不同。

**直接排序的正确目标**：若能估计同一 query 候选身份的正确概率，按概率降序排位可最大化期望 MRR；门控只是估计不可靠时的保守动作。一个整体 top-1 较弱的模型仍可能在底座错误的子集上提供增量。必须测错误互补与配对 Δ，不能用不同面板的两个 top-1 数字排除融合。

### 2.3 “p=1，所以加 1 且零下行”的推导也不对

[一致性门第 47–50 行](/Users/zhaohuaxiang/ccjjllt/enveda/rounds/070-generation/research/070-agreement-gate.md:47)同时说 `p=1` 时安全，又给出 `Δ=1-1.5c`，两者自身矛盾。真实真值被提升时，若原 rank=2，增益是 0.5；rank=5 是 0.8；原 rank=1 是 0。即使所有门控正确，收益也应由旧名次分布算，不能把“修正了多少题”全部按 +1 计。

**若真实部署分布上 p 确实等于 1，操作当然不降分；但 392 条校准查询零错并不证明部署 p=1。** 这些查询不是已经核实的 392 个独立结构，且阈值由同一面板扫描选择；目前不应据此计算有效置信区间。16–40 候选层只点火 25 条查询，同样不足以声称“候选多时安全性不退化”。必须取得结构分组、训练曝光和锁定折后重新统计。

### 2.4 尾槽收益小是真的，“生成结构上不能提分”是假的

只改第 23–25 名时，每个分子最好新增 `1/23≈0.04348`，并存在挤出原真值的代价。这解释了尾槽策略难以带来大幅提升。旧文档的 `+0.0004~+0.0013` 却依赖未测的 28% 缺失率及外部文献精度迁移，不是本赛硬上限。生成候选若能被校准到第 1–5 名，适用的是前述插入收益式；若只补尾，应该报告“预期收益较小”，不能否定整个生成类别。

## 3. 083a 已确认的推理缺陷与校准风险

### 3.1 已确认：先平均峰序列，产生伪谱

本次从[公开 hengck23 数据集](https://www.kaggle.com/datasets/hengck23/hengck23-dreams-enveda-casmi26)只下载 `dreams_minimal_model.py`（21,916 B）。SHA-256：`e7021a21e7b229cac99b4ec37dbfd85cf4044195d8245ff9c57f923eb2d3ff66`。

- `preprocess_spectrum` L589–685：输出 **[101,2] 的原始 `[m/z, intensity]` 序列**；取最强 100 峰但恢复原顺序、零填充，并在第 0 行加 precursor token。
- `DreaMSBackbone.forward` L498–529：把该张量当真实 m/z 与相对强度，按 m/z=0 识别 padding，再计算峰与 Fourier 编码。
- [083a notebook](/Users/zhaohuaxiang/ccjjllt/enveda/rounds/070-generation/083a/enveda-083a-agreegate.ipynb) cell 27 L91–105：先逐谱 `preprocess_spectrum`，L102 对每个分子的数组逐位置平均，L104 才 `embed_preprocessed`。

峰序列位置不是固定 m/z 网格。两张谱第一峰分别 m/z 100、120，平均后会出现 m/z 110；一张谱有峰而另一张对应行 padding 为 0，还会把峰移到一半 m/z。不同加合物的 precursor token 也被平均。这与“多谱 embedding 求均值”不同，不能视作合法的共识谱。

**待实施的修正实验**：每张谱独立预处理、独立 DreaMS 编码；再比较两种清楚定义的分子聚合：①每谱 embedding 归一化后按分子求均值，再送对齐 head；②每谱送 head 并计算各候选分数，再按分子聚合分数。二者不等价，必须以训练约定为准或重新标定，不能随手选一个后继承旧 1.000 精度。按极性/加合物或 CE 分组可作后续消融。正确修复首先消除表示错误，**是否提分未测**。

对每题只在评估进程中加入真值位置，输出一个首个失败原因：

- F0：真值不在任何允许的候选数据库；
- F1：数据库含真值，但中性质量/加合物/公式筛选丢失；
- F2：窗口含真值，但便宜检索 pass-1 丢失；
- F3：pass-1 含真值，但来源 topK 截断丢失；
- F4：来源 union 含真值，但融合/配额截为 25 时丢失；
- F5：最终 25 含真值，但 rank>1；
- F6：rank1 正确。

同一个错误只能进入首个失败类别，才能量化下一步应该扩大池、扩大候选宽度、换检索器、改融合还是训排序。e180 的已知真值加随机同式 decoy 面板保留作单模型诊断，不能替代这个账本。
